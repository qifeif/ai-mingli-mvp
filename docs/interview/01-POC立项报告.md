# 心易 AI 命理决策助手 · POC 立项报告

## 1. 项目背景

传统命理、风水、六爻等内容长期存在稳定需求，但线上产品普遍有三类问题：

- 结果黑箱：用户拿到“吉凶结论”，但不知道依据是什么。
- 语言门槛高：紫微、十神、四化、卦象、方位等术语密集，普通用户难以理解。
- 风险边界弱：不少产品会直接给确定性判断，甚至触及健康、生死、投资等高风险场景。

本项目希望验证一种新的产品形态：把命理排盘作为结构化输入，把 AI 解读作为表达层和陪伴层，最终服务于“自我认知与决策辅助”，而不是替用户做决定。

## 2. POC 目标

POC 阶段验证三个核心假设：

| 假设 | 验证问题 | 成功标准 |
| --- | --- | --- |
| H1 需求成立 | 用户是否愿意用 AI 命理工具讨论真实问题 | 首次排盘完成率 >= 70%，生成后追问率 >= 30% |
| H2 技术可行 | 传统术数能否被结构化计算并交给 LLM 解读 | 排盘接口稳定返回，核心字段可被前端渲染与模型引用 |
| H3 体验差异成立 | AI 是否能把术语转成可理解建议 | 人工评分中“白话可懂”平均 >= 4/5 |

## 3. 产品定位

产品名：心易

一句话定位：一个结合传统术数与 AI 的命理决策助手，帮用户从天命、地运、人事三个角度看清问题。

产品边界：

- 做：排盘、解释、追问、对照、启发、风险提示。
- 不做：确定性预测、替用户决策、医疗/法律/投资建议、恐吓式断语。

## 4. 目标用户

| 用户类型 | 典型问题 | POC 价值 |
| --- | --- | --- |
| 职业决策用户 | 要不要跳槽、创业、考研 | 用命盘节奏辅助拆解决策 |
| 情感关系用户 | 要不要继续关系、如何相处 | 用合参与对话解释互动模式 |
| 居住环境用户 | 房间布局、办公位、睡眠方向 | 用八宅方位给空间建议 |
| 命理兴趣用户 | 想看紫微盘、六爻卦、术语含义 | 提供可视化与白话解释 |
| 高敏感情绪用户 | 焦虑、低谷、无助 | 先做安全拦截，不进入命理流程 |

## 5. POC 范围

本轮 POC 选取“四条主路径”：

1. 天命：紫微斗数排盘与 AI 解读。
2. 地运：八宅方位推荐与户型图视觉点评。
3. 人间道：六爻起卦与卦象解读。
4. 合参：双人八字对照，面向婚恋与合伙关系。

同时验证两个横向能力：

- 对话追问：用户可基于已有结果继续问。
- 危机拦截：自伤、自杀、极端绝望等内容优先进入安抚与求助流程。

## 6. MVP 功能清单

| 模块 | POC 功能 | 验证重点 |
| --- | --- | --- |
| 天命 | 真太阳时校正、紫微十二宫、三方四正、AI 深化 | 排盘准确性、解读可懂性 |
| 地运 | 本命卦、八方位吉凶、诉求方位推荐、户型图点评 | 空间建议是否可操作 |
| 人间道 | 三铜钱摇卦、本卦/动爻/变卦、AI 解读 | 问事场景是否成立 |
| 合参 | 双人八字、十神互动、地支合冲刑害、五行互补 | 是否能解释关系模式 |
| 对话 | 多轮问答、跨页上下文接力 | 是否像同一场咨询 |
| 安全 | 危机检测、命理短路、安抚话术 | 是否避免高风险误导 |

## 7. 技术验证范围

POC 技术策略是“确定性计算 + LLM 表达”的分层架构：

- 纯计算层：紫微、八字、八宅、六爻、合参基础结果不依赖模型。
- 知识层：本地 Markdown/JSON 知识库通过 RAG 检索注入。
- 模型层：支持 Anthropic 与 OpenAI-compatible provider。
- 交互层：关键长任务使用 SSE 流式输出，降低等待感。
- 数据层：未登录使用 localStorage，登录后通过 Supabase 保存用户数据。

## 8. 验证指标

| 指标类型 | 指标 | 目标 |
| --- | --- | --- |
| 功能稳定性 | 核心排盘接口成功率 | >= 99% |
| 首轮体验 | 命盘骨架返回时间 | < 1s |
| AI 体验 | 主解读可读性人工评分 | >= 4/5 |
| 安全 | 危机场景漏拦率 | 0 容忍 |
| 留存倾向 | 解读后追问率 | >= 30% |
| 产品理解 | 用户能否说出“下一步怎么做” | >= 70% |

## 9. 主要风险

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 宿命化表达 | 模型说“你一定会”“注定失败” | system prompt 红线 + Bad case 回归 |
| 术语过载 | 用户看不懂巨门、化忌、绝命等词 | 首次出现必须括注白话解释 |
| 排盘误差 | 出生地/时辰错误导致整盘变化 | 真太阳时校正、出生地提示、示例盘降级 |
| 高风险误导 | 健康、生死、投资等场景被命理解读 | 危机检测与禁区规则优先 |
| 模型不稳定 | 不同模型输出风格差异大 | 建立评测集，固定评分维度 |

## 10. 里程碑

| 阶段 | 目标 | 产物 |
| --- | --- | --- |
| POC 第 1 周 | 跑通天命、地运、人间道纯计算 | API + 页面雏形 |
| POC 第 2 周 | 接入 LLM 解读与危机拦截 | 主解读链路 |
| POC 第 3 周 | 加入合参、RAG、对话追问 | 四道联动 |
| POC 第 4 周 | 做 UX 审计与模型评测 | 评测报告 + Bad case |

## 11. POC 结论

POC 具备继续推进价值。原因如下：

1. 核心术数可以被拆为稳定的结构化计算，不必让模型“凭空算命”。
2. 大模型更适合承担解释、转译、承接上下文与对话陪伴，而非负责事实计算。
3. 命理类产品的关键壁垒不是单点排盘，而是“可信结构 + 白话表达 + 安全边界 + 可追问体验”的组合。
